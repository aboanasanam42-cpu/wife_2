# MEXC Futures Grid Worker

عامل Python يعمل كـ Railway Worker لاستراتيجية Long Grid على عقد MEXC USDT-M الدائم `BTC/USDT:USDT`.

الإعداد الافتراضي: نطاق 84,000 إلى 84,700 USDT، مستويان (شراء عند الحد الأدنى وجني ربح عند الحد الأعلى)، رافعة 10x، هامش مستهدف 5 USDT وقيمة اسمية مستهدفة 50 USDT لكل دورة. يفتح العامل مركزًا واحدًا فقط؛ القيمة والهامش الفعليان يتأثران بمواصفات العقد والرسوم ومتطلبات الصيانة.

يتحقق العامل من السوق وحجم العقد وحدود ودرجات دقة السعر والكمية، ويستخدم وضع CCXT `swap` و`linear` وتسوية USDT. أي أمر غير معروف على الزوج أو مركز لا يمكن ربطه بحالة البوت يوقف إنشاء الأوامر تلقائيًا. يستخدم `amount_to_precision` و`price_to_precision` قبل الإرسال.

## التشغيل الآمن

`LIVE_TRADING=false` هو الافتراضي؛ يقرأ العامل الأسعار ويطبع المستويات دون إرسال أوامر. التداول الحقيقي يتطلب مفتاح MEXC بصلاحيات Futures المناسبة، رصيدًا كافيًا، ووضع مركز One-way على حساب مخصص لهذا الزوج. يطلب العامل ضبط الرافعة إلى 10x ويتوقف إذا رفضت المنصة الطلب. لا يغيّر وضع المركز تلقائيًا.

تُخزّن حالة الدورة عبر `BOT_STATE_FILE`. في Railway، اربط Volume دائمًا بمسار `/data` واضبط `BOT_STATE_FILE=/data/wife_2_state.json`. من دون تخزين دائم لا يمكن ضمان استعادة الدورة بعد إعادة إنشاء الحاوية؛ عند اكتشاف مركز أو أمر غير معروف سيتوقف العامل بدل فتح صفقة أخرى. قفل الملف يمنع تشغيل نسختين تستخدمان ملف الحالة نفسه.

## Railway والإعداد

يستخدم `Procfile` الأمر `worker: python bot.py` و`runtime.txt` Python 3.11. أنشئ خدمة Worker من المستودع، واربط Volume كما سبق، وأضف `MEXC_API_KEY` و`MEXC_API_SECRET` و`LIVE_TRADING` من إعدادات Railway فقط. لا تحفظ المفاتيح في GitHub أو ملفات المشروع. بقية القيم الافتراضية موضحة في `.env.example`.

GitHub Actions يثبت التبعيات ويتحقق من الصياغة والاستيراد ويشغّل اختبارات الوحدة. الاختبار المحلي: `python -m unittest discover -s tests -v`.

لا يضمن هذا البرنامج ربحًا. تحقق من إعداد الحساب والاتصال الحي والسجلات، وابدأ بوضع القراءة فقط قبل اتخاذ قرار تفعيل التداول الحقيقي.
